# Sri Lankan Geographical & Postal Code Dataset Research

## Executive Summary

An audit of `e:\EAD` shows that the current geographical reference dataset (`data/geo/curated/sri-lanka-geo-bundle.json` and `data/geo/raw/*.csv`) is a **minimal seed/sample dataset** generated by `scripts/geo-etl/etl.py`—containing **9 provinces, 25 districts, 33 DS divisions, 16 GN divisions, and 42 postal areas**—rather than a full island-wide dataset.

No single primary source provides all seven required fields (`postal_code`, `area_name`, `province`, `district`, `ds_division`, `gn_division`, `latitude`/`longitude`) in one complete, authoritative file. To populate SwiftDrop's full schema (`V6__create_geographical_reference_tables.sql`) with island-wide coverage (~1,830+ postal areas, ~331–339 DS divisions, and ~14,022–14,043 GN divisions), the ETL pipeline must **combine and cross-validate two complementary tiers of primary sources**:

1. **Authoritative Administrative Hierarchy (Provinces -> Districts -> DS Divisions -> GN Divisions):**
   - **Survey Department / UN OCHA HDX COD-AB (`cod-ab-lka`)** for official GIS boundaries/centroids, or **Praja Dev `lk-data` (CC0-1.0)** / **DCS Census Codes (`statistics.gov.lk`)** / **MOHA (`moha.gov.lk`)** for tabular codes and names.
2. **Authoritative Postal Codes & Coordinates:**
   - **Sri Lanka Post (`slpost.gov.lk` / `POST-CODE-BOOK-.pdf`)** as the canonical 5-digit postal code & post-office authority, paired with **GeoNames (`LK.zip`, CC BY 4.0)** and **`slwdc/Postal-Codes` (MIT)** / **`SKIDDOW/SriLankaCitiesDatabase` (MIT)** for machine-readable coordinates and area names.

## 1. Current Repository State (`e:\EAD`)

### 1.1 Existing Scripts & Pipeline
* **ETL Script:** `scripts/geo-etl/etl.py` (with unit tests in `scripts/geo-etl/test_etl.py`).
  * Reads 6 CSVs from `data/geo/raw/`: `provinces.csv`, `districts.csv`, `ds_divisions.csv`, `gn_divisions.csv`, `sl_post_reference.csv`, and `postal_codes.csv`.
  * Normalizes names and 5-digit `postal_code` values (`^\d{5}$`), validates every `postal_codes.csv` row against `sl_post_reference.csv` (rejecting unverified codes and flagging province/district mismatches), and writes:
    * `data/geo/curated/sri-lanka-geo-bundle.json` (import version `2026.11.1`)
    * `data/geo/curated/validation-report.json`
* **Spring Boot Importer:**
  * `services/organization-service/src/main/java/com/swiftdrop/organization/service/GeoImportService.java` — idempotently upserts `provinces`, `districts`, `ds_divisions`, `postal_areas`, and `gn_divisions` from `sri-lanka-geo-bundle.json` without touching `branch_postal_areas`.
  * `services/organization-service/src/main/java/com/swiftdrop/organization/config/GeoImportRunner.java` — `@Profile("!test")` `CommandLineRunner` that loads `file:data/geo/curated/sri-lanka-geo-bundle.json` (or `file:../../data/geo/curated/sri-lanka-geo-bundle.json`) on boot.
* **Schema & Specs:**
  * `services/organization-service/src/main/resources/db/migration/V6__create_geographical_reference_tables.sql`
  * `.scratch/branch-postal-area-management/spec.md` & `issues/01-geo-data-location-apis-and-cascading-ui.md`

## 3. Target Schema Field Mapping (`V6` & `GeoImportService.java`)

| SwiftDrop Table / Field | Target Type | Best Primary Source | Fallback / Enrichment |
| :--- | :--- | :--- | :--- |
| `provinces` (`code`, `name`, `lat`, `lon`) | `VARCHAR(20)`, `VARCHAR(120)` | `praja-dev/lk-data` / HDX `cod-ab-lka` ADM1 | Centroid from HDX `cod-ab-lka` polygons |
| `districts` (`code`, `province_code`, `name`, `lat`, `lon`) | `VARCHAR(20)`, `VARCHAR(120)` | `praja-dev/lk-data` / HDX `cod-ab-lka` ADM2 | Centroid from HDX `cod-ab-lka` polygons |
| `ds_divisions` (`code`, `district_code`, `name`, `lat`, `lon`) | `VARCHAR(30)`, `VARCHAR(150)` | HDX `cod-ab-lka` ADM3 (`ADM3_PCODE`) or `praja-dev/lk-data` | Centroid from HDX `cod-ab-lka` ADM3 polygons |
| `gn_divisions` (`code`, `ds_division_code`, `name`, `postal_code`, `lat`, `lon`) | `VARCHAR(30)`, `VARCHAR(150)`, `VARCHAR(5)` | HDX `cod-ab-lka` ADM4 (`ADM4_PCODE`) or `praja-dev/lk-data` | `postal_code` is **optional** (`null` when unmapped); can be approximated via nearest/containing `postal_areas` centroid or left `null` (supported by `GeoImportService.java` L193). |
| `postal_areas.postal_code` | `VARCHAR(5)` (`^\d{5}$`) | **Sri Lanka Post (`POST-CODE-BOOK-.pdf` / `slpost.gov.lk/postcodes/`)** | Cross-checked against `GeoNames LK.zip` + `slwdc/Postal-Codes` |
| `postal_areas.area_name` | `VARCHAR(200)` | Sri Lanka Post / `slwdc/Postal-Codes` / GeoNames `place_name` | Normalized title case via `etl.py` |
| `postal_areas.province_code` & `district_code` | `VARCHAR(20)` | GeoNames `admin_name1`/`admin_name2` + `slpost.gov.lk` district | Verified against `sl_post_reference.csv` |
| `postal_areas.ds_division_code` | `VARCHAR(30)` (nullable) | **Spatial join** of `(latitude, longitude)` against HDX `cod-ab-lka` ADM3 polygons | Nullable in `V6` (`ds_division_id REFERENCES ds_divisions(id)`) |
| `postal_areas.latitude` / `longitude` | `DOUBLE PRECISION` | GeoNames `LK.zip` + `slwdc/Postal-Codes` + `SKIDDOW/SriLankaCitiesDatabase` | Geocoding fallback for Northern Province gaps |

## 4. Recommended Fetch & Curation Workflow

To upgrade `data/geo/raw/*.csv` from the 42-row sample to a complete island-wide dataset without modifying `GeoImportService.java` or `V6`:

1. **Fetch Administrative Divisions (`provinces.csv`, `districts.csv`, `ds_divisions.csv`, `gn_divisions.csv`):**
   - Download **HDX `cod-ab-lka`** (`lka_admin_boundaries.gdb.zip` or `.shp.zip`) from `https://data.humdata.org/dataset/cod-ab-lka` (or `praja-dev/lk-data` CSVs if polygons aren't needed).
   - Extract ADM1–ADM4 tables using Python (`geopandas` / `pyogrio`), computing polygon centroids (`latitude`, `longitude`) for all 9 provinces, 25 districts, ~339 DS divisions, and ~14,043 GN divisions, using `ADM*_PCODE` (truncated/mapped to `<= 30` chars) as `code`.
2. **Build Authoritative Reference (`sl_post_reference.csv`):**
   - Parse `POST-CODE-BOOK-.pdf` (`https://slpost.gov.lk/wp-content/uploads/2022/11/POST-CODE-BOOK-.pdf`) with `pdfplumber` / `pypdf` (or scrape `https://slpost.gov.lk/postcodes/`) to obtain the complete canonical list of valid 5-digit `postal_code`, `area_name`, `district_name`, and `province_name`.
3. **Merge & Enrich Postal Areas (`postal_codes.csv`):**
   - Download `https://download.geonames.org/export/zip/LK.zip` and `https://raw.githubusercontent.com/slwdc/Postal-Codes/master/Postal_Codes.csv` (plus `SKIDDOW/SriLankaCitiesDatabase` `cities.json` for Northern Province gaps).
   - Merge by 5-digit `postal_code` (preferring Sri Lanka Post for `area_name`/district/province, and GeoNames/`slwdc` for `latitude`/`longitude`).
   - Run a point-in-polygon spatial join (`shapely` / `geopandas`) against HDX `cod-ab-lka` ADM3 polygons to populate `ds_division_code` for each postal area (leaving `ds_division_code` empty where coordinates are missing or coastal).
4. **Validate & Emit Bundle:**
   - Run `python scripts/geo-etl/etl.py --import-version <version>` to validate every postal code against `sl_post_reference.csv`, emit `data/geo/curated/sri-lanka-geo-bundle.json` and `data/geo/curated/validation-report.json`, and review `rejected` / `conflicts` before booting `organization-service` with `GeoImportRunner`.
